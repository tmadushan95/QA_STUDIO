Page · Projects and Project settings

Project settings: set up once

Application and sign-in

The app’s address and how a run signs in: a login form, a saved session, or none.

Versions

Releases such as 2.4 or Sprint 18. One can be current. Deleting one keeps its cases.

Test suites

Folders for cases. A suite that still holds cases cannot be deleted by accident.

Parameters

Values every case of the project shares, such as a project code.

Custom steps

The project’s own reusable steps, built from standard ones, for example “Create a draft project”.

Sign-in users

Test accounts such as “Approver”. Passwords are encrypted and never shown again.

Business value: each client application is configured once by a lead; testers then just pick the project and work.

This is the master data: Project, then Version, then Test suite, then Test case. Stress the safety rules, they reassure clients: • A project that still has suites or accounts, or a suite that still has cases, cannot be deleted. One click can never wipe a test library. • Passwords for test accounts are encrypted at rest and never sent back to the browser. Custom steps are a strong selling point for leads: they package a common flow (for example “log in and open the reports page”) into one named step with inputs. Testers then use it like any built-in step, and if the flow changes it is fixed in one place.
