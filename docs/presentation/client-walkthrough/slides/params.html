Rule 3

Named clearly at run time; it never half-runs.

Auto-fill fills empty values for review: earlier test data, then AI, then a guess from the name. Names that look like passwords, tokens or keys are never filled.

Steps refer to values by name, written {{data.name}}, so the same case can run with different data and nothing sensitive is typed into the steps themselves. Explain the three rules simply: the case’s own value, else the project’s shared value, else the case is blocked before it starts, with the missing name shown. Blocked is different from failed: it means “not runnable yet”, not “the app is broken”. Auto-fill saves a lot of typing when many cases are imported at once. It only fills empty values and never overwrites what a person set. Credentials never go here; they belong to Sign-in users, where they are encrypted.
