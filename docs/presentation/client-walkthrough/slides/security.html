Engineering quality · Security and safety

Safe by design

Checks at the edge

Host and origin checks, then an access token or session, before any endpoint or forward.

Secrets stay secret

Passwords and keys encrypted at rest, never returned, stripped from AI prompts.

Allowed targets only

Runs go only to allow-listed environments; production is refused.

No half-runs

All steps validated before any runs; data-deleting steps only where allowed.

No silent overwrites

Row versions turn a stale save into a clear conflict.

Human in the loop

AI only drafts; voice confirms deletes; agents cannot approve.

Security questions usually come up here; this slide answers most of them. Edge checks: the host check stops DNS-rebinding tricks; the origin check stops another website from driving the API through a user’s browser; an optional access token or session protects everything except health and sign-in. API and worker trust each other through a shared internal token; the worker is never exposed to the browser. The encryption key for stored passwords and AI keys is created on first run and must be backed up: without it, stored secrets cannot be decrypted. The common thread: every new entry point, whether AI, voice or MCP agents, goes through the same rules as a click. There is no side door.
