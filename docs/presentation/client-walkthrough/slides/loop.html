How it works

One loop: from test idea to evidence

1

Create

From Excel, AI, by hand or Azure DevOps.

→

2

Add steps

Visual editor, or written from the case text or by AI.

→

3

Approve

Checked automatically, approved by a person: “Ready to run”.

→

4

Run

A real browser signs in as a test user and runs the steps.

→

5

Review

Live results, screenshots, traces, reports, dashboard.

Closing the loop

A failed case can be explained by AI. An out-of-date test gets a fix draft; a likely defect goes to the developers.

Everything is scoped

Every case lives in one project, one suite and optionally one version, like an Azure DevOps project and branch.

This is the core business process. Every page in the product supports one of these five steps, and I will refer back to the numbers as we go through the pages. 1 Create: four sources, so the client keeps using what they have today (Excel sheets, Azure Test Plans). 2 Add steps: the visual editor, or let the system convert the written steps, or AI. 3 Approve: nothing runs until it passes validation and a person approves. This is the control point managers like. 4 Run: a real Chromium browser, signed in as a test account. 5 Review: live view, evidence and the dashboard. Then the loop closes: failures feed back into fixes.
