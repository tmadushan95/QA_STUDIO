This is the slide for the technical people. QA Studio is three programs. 1 The web app (React, TypeScript): only the user interface. It talks to one address only. 2 The .NET 10 API: the front door. It owns security and the database, and implements the core business data: projects, suites, versions, test cases and the dashboard. Anything it does not implement itself it forwards to the worker, through a built-in reverse proxy (YARP). 3 The Node.js worker: everything that is best done in Node: driving the browser with Playwright, the step engine, Excel import, reports and AI. SQL Server holds all data. The worker has no database of its own: it loads a snapshot at start-up and writes changes back through the API’s internal routes in ordered batches. A save is only confirmed to the user once it is in the database. Why two backends? Playwright and the step engine are strongest in Node; storage, security and business rules are strongest in .NET. Because of the gateway, features can move from the worker to .NET one by one with no change to the web app.
