Architecture · Web app

The web app: small, focused pieces

Features

One folder per page, each with its own api.ts.

Templates and organisms

App layout, dialogs, data tables, panels.

Molecules

Field, menu, tabs, alert, status badge.

Atoms and tokens

Button, icon, inputs; colours and spacing set once.

No global store

Each screen loads what it needs; a live event says “changed” and the screen refetches.

One shared scope

A context provider holds project and version for every page.

Works on any screen

Sidebar on desktop, icon rail on tablet, drawer and bottom bar on phones.

Accessible by default

Keyboard support, labelled inputs, automated axe checks on every page.

Atomic Design: the design system is built from atoms (buttons, inputs) up to molecules, organisms and page templates. It knows nothing about the business and never calls the API. Features own their screens and their own api.ts, the only place that builds that feature’s requests. No Redux: server data stays on the server. Two custom hooks do the work: useResource loads data and ignores stale answers, useLive subscribes to the one shared live-event connection. This is why live updates are simple and never get out of sync. Pages are lazy-loaded so the first load is fast. Colour is never the only signal; every status also has a word or an icon.
