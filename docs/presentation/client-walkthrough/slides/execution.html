This is loop step 4. Only cases marked “Ready to run” appear here. The three run modes answer a real business question: speed versus isolation. • Fresh window is the recommended default: fast because each user signs in only once, but clean because nothing carries over between cases. • Same window is fastest but one case can affect the next. • Concurrent users is for multi-user scenarios: an approver and a requester at the same time, or the same user in two browsers to check a double submit. Safety: runs are only allowed against environments on an allow-list, so nobody can point QA Studio at production by mistake. Outside concurrent mode one account never runs in two browsers at once.
