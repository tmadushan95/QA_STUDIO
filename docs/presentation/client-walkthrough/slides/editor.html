Parameters as chips

Drafts never break runs

A save with problems stays a draft; the last valid version keeps running. A stale save is refused, not overwritten.

The popup for a case has five tabs: Steps, Details, Parameters, Runs and History. This slide is the Steps tab. Key points: • Each step card is drawn from a catalog the server sends. When we add a new kind of step, it appears in the editor with no change to the web app. • Elements are described by role and name (“the button named Delete, inside the dialog”), which is how Playwright finds them. This is far more robust than CSS selectors when the page layout changes. • Validation runs as you type, so a broken step is visible immediately. • If two people edit the same case, the second save is refused with a clear message and an offer to reload, instead of silently losing the first person’s work. Example values on the slide are illustrative.
