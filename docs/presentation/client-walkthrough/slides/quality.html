A test pyramid: many fast unit tests on pure rules, fewer integration tests, and a smaller number of whole-app UI tests. Integration tests create a temporary database with a unique name and drop it afterwards, so they never touch real data. The UI tests render the whole app against a fake server and run automated accessibility checks (axe) on every page. For developers, the Aspire dashboard shows one click followed through the API, the gateway and the worker as a single timeline, which makes problems much faster to diagnose. It is a development tool only; installs stay simple. Rule of thumb we follow: put a rule in a pure function, test it with plain inputs, and test the wiring only once.
