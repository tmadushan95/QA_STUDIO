One project and version picker for the whole app, so two pages can never disagree about scope. Deep links work: any address can be bookmarked or shared.

Explain the mental model before showing pages. If the client uses Azure DevOps, this is instantly familiar: organisation, then project, then a branch-like version. Points to make: • The header is the only place you choose project and version, so every list, run and chart agrees. • Versions are releases such as “2.4” or “Sprint 18”; one can be marked current. • Clean web addresses mean a tester can send a colleague a link straight to a page. Engineering note if asked: a React context provider (ProjectScope) holds the scope; pages are lazy-loaded so the first load stays fast.
