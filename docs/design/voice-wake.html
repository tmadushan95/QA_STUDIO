Behaviour rules

Decisions behind the design

  • The mic indicator is always visible. In standby the top bar shows a breathing dot and the phrase. Users always know QA Studio can hear them.
  • The hint teaches the phrase. The pill shows the exact words to say. A one-time coach mark explains privacy, and push to talk is always shown as a fallback.
  • Wake gets confirmation within 300 ms. A tone, a toast and the dock appear before the room finishes connecting, so a missed wake is obvious.
  • What voice changes is shown on screen. Coverage and format controls flash when voice sets them, and the description field is marked “from voice”.
  • Saving always needs a confirmation. The agent asks, and the Save button is highlighted at the same time. Saying “yes” or clicking does the same thing.
  • It talks like a colleague. Short turns, plain acknowledgements (“Got it”), and you can interrupt at any time. It asks one question at a time, with choices, only when the answer changes the cases.
  • It asks instead of guessing. Missing roles, flows or data become a question, never an invented URL or value. “You decide” lets the agent pick and say what it assumed.
  • The session ends predictably. A ring counts down the last 8 seconds of silence. Any speech resets it.
  • Errors say how to fix them. For a blocked mic, show the browser’s site-settings path. If LiveKit is not set up, name the server variables.
  • Keyboard users get parity. Ctrl Space talks, Esc ends, and state changes are announced through a polite live region.
  • Respects reduced motion. The orb and ripples stop moving. State is still shown by labels and colour.
