QA Studio · how a test case runs

From a written test case to a real browser click

QA Studio never writes Playwright script files. It turns each test case into a short list of steps stored as data, and the worker runs them with Playwright functions that are written once. This page follows one test case through every stage and shows which folder does what.

1. Steps are data"Click the Save button" becomes { action: "click", target: { role: "button", name: "Save" } }.
2. Playwright code is fixedEach action (click, fill, open…) is one small function that already holds the Playwright code.
3. Run = data + functionsAt run time each step picks its function, builds a locator and acts in the browser.

    Locator rules

    How a target picks its Playwright locator

    A target describes an element the way a person or a screen reader would, never by CSS class or XPath. locate() uses the first field that is filled in, in this order, then adds .first() (or .nth(n)).

    #Target fieldPlaywright callFinds, for example
    1testIdgetByTestId("save")<button data-testid="save">
    2role + namegetByRole("button", { name: "Save" })<button>Save</button> or an icon button with aria-label="Save"
    3labelgetByLabel("Name")The input tied to <label>Name</label>
    4placeholdergetByPlaceholder("Search…")<input placeholder="Search…">
    5textgetByText("Project saved")Any element showing that text
    +withinFind the container first, then search inside it"The Delete button in the row containing PRJ-001"
    +exact, nthWhole-text match; pick the 2nd, 3rd… matchWhen several elements fit

    Words used here

    Glossary

    Test case (TC)
    What a tester writes in plain English: steps and expected results.
    Scenario / steps
    The same test case as a list of { action, params } records, stored in SQL Server. A draft until someone approves it.
    Action
    One kind of step (click, fill, open, assert-text…). Each is a function in actions.ts holding the Playwright code.
    Target
    How to find an element: role, name, label, placeholder, text or test id. Never CSS or XPath.
    Locator
    Playwright's handle to an element, for example page.getByRole("button", { name: "Save" }).
    Run mode
    Concurrent: fresh browser per case. Clean: one browser, a new window per case, signs in once. Shared: one window per account, reused.
    Blocked
    The case did not run: a bad step, missing data, a missing password or failed sign-in.
    Destructive step
    A step that deletes or changes data. It runs only when QA_ALLOW_DESTRUCTIVE=true.
